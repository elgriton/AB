## Pinch of Flavor

Учебный сайт блога с рецептами на PHP и Smarty. Главная показывает подборки рубрик, рубрика — список рецептов с сортировкой и пагинацией, страница рецепта — полный текст, категории, теги и похожие записи.

AI-агенты использовались:
Figma — разработка макета (pre/design_figma.png)
Codex — выполнение задач из AGENTS.md, написание README.md, PHPDoc

## Требования

- PHP 8.1 или новее с PDO MySQL и расширением `mbstring`.
- MySQL или MariaDB с доступом пользователя, которому разрешено создавать базу данных.
- Composer.
- Веб-сервер Apache с `mod_rewrite` и разрешёнными правилами `.htaccess` (нужен для `/sitemap.xml`).

Проект использует Smarty 5 (`smarty/smarty`). PHP-расширения и точные версии MySQL в репозитории отдельно не закреплены.

## Установка и запуск

1. Установите PHP-зависимости командой `composer install`.
2. Установите инструменты сборки стилей командой `npm.cmd install`.
3. Разместите проект в корне сайта Apache и откройте `index.php`.
4. При отсутствии корректной конфигурации откроется форма подключения и установки базы. Укажите хост, порт, имя базы, пользователя и пароль.
5. После установки параметры подключения сохраняются в локальный `config.php`; схема и демонстрационные записи создаются автоматически.

`config.php` содержит локальные параметры подключения и не должен добавляться в Git. Для повторного наполнения пустой базы используется `DatabaseSeeder` при проверке установки.

## Запуск через Docker

Для запуска в контейнерах нужны Docker Desktop с запущенным Docker Engine и Docker Compose. Локальные PHP, Apache, MySQL и Node.js для запуска сайта этим способом не требуются.

Из корневой папки проекта выполните в PowerShell:

```powershell
docker compose up -d --build
docker compose ps
```

После запуска откройте [http://127.0.0.1:8080/](http://127.0.0.1:8080/). При первом запуске заполните форму подключения к базе:

| Поле | Значение |
| --- | --- |
| Хост | `db` |
| Порт | `3306` |
| Имя базы | `recipe_blog` |
| Пользователь | `recipe_user` |
| Пароль | `recipe_password` |

Эти значения соответствуют текущему `compose.yaml`. Внутри Docker хост базы — `db`; `127.0.0.1` или `localhost` указывали бы на контейнер приложения. После отправки формы приложение создаст таблицы и добавит начальные рецепты.

Полезные команды:

```powershell
docker compose logs -f app  # Смотреть журнал приложения
docker compose stop        # Остановить контейнеры, сохранив их
docker compose start       # Запустить остановленные контейнеры
docker compose down        # Удалить контейнеры и сеть, сохранив данные базы
```

Данные MySQL хранятся в именованном томе `mysql_data` и переживают `docker compose down`. Команда `docker compose down -v` удаляет этот том вместе с базой — после неё данные придётся создать заново.

При первоначальной настройке `config.php` создаётся внутри контейнера приложения. Если контейнер приложения удалить и создать заново, может потребоваться снова заполнить форму подключения. Это не удаляет базу, хранящуюся в `mysql_data`.

Учётные данные в `compose.yaml` предназначены для локального тестового окружения. Перед размещением проекта в общем или публичном окружении замените их и не публикуйте реальные пароли.

## SCSS и CSS

Исходники стилей находятся в `assets/scss/`, а браузер получает скомпилированные CSS-файлы из `assets/css/`. `site.scss` содержит мобильные и общие стили, `site-desktop.scss` — правила для широких экранов. Палитра и повторно используемые значения вынесены в `assets/scss/_tokens.scss`.


```powershell
npm.cmd install
npm.cmd run scss:build
```

Для автоматической пересборки при изменениях запусти `npm.cmd run scss:watch` и оставь процесс работающим. Изменяй SCSS-файлы, а не сгенерированные CSS.

## Основные адреса

- `index.php` — главная.
- `index.php?category={slug}` — рубрика; поддерживает `sort=date|views` и `page=N`.
- `index.php?post={slug}` — отдельный рецепт.
- `sitemap.xml` — карта сайта, генерируемая из текущих рубрик и рецептов базы данных.
- `robots.txt` — разрешает роботам получать страницы, чтобы они видели директиву `noindex`; закрывает `/admin/`.
- `admin/admin.php` — тестовая административная часть.

## Структура

- `app/Controller/` — маршрутизация и подготовка данных страниц.
- `app/Repository/` — SQL-запросы к базе данных.
- `app/Core/` — PDO-подключение и Smarty-рендерер.
- `app/Infrastructure/` — конфигурация, схема, установка и начальное заполнение базы.
- `templates/` — Smarty-шаблоны, layouts и общие partials.
- `assets/scss/` — исходники Sass; `_tokens.scss` — общие переменные палитры.
- `assets/css/` — скомпилированные стили, подключаемые страницами сайта.
- `assets/images/` — SVG-изображения, favicon и заглушка рецепта.
- `database/` — вспомогательный скрипт заполнения базы.
- `storage/` — скомпилированные Smarty-шаблоны и кеш; содержимое генерируется приложением.
- `vendor/` — Composer-зависимости; содержимое генерируется Composer.
- `pre/` — материалы, оставленные в проекте.

## Индексация

Сайт закрыт от индексации: HTML-страницы и PHP-ответы отдают директиву `noindex`, а `robots.txt` разрешает поисковым роботам прочитать её. Каталог админки дополнительно закрыт от обхода.
